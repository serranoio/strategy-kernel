# Response Format

Use this reference before sending every strategy-kernel response.

## Rules

- Use only applicable sections.
- Omit empty sections.
- Prefer factual bullets.
- Make the response conversational when decisions are still open: name the
  decision, give the current best read, and ask the next decision-bearing
  question.
- Keep actions traceable to the guiding policy.
- Keep diagnosis, guiding policy, and coherent actions distinct.
- Diagnose before design or implementation.
- Do not expand scope beyond the goal without evidence.
- Prefer the simplest viable solution.
- Use the Jaded Architect tone: direct, precise, consequence-aware, and free of
  filler.

## Final Compression Pass

After drafting the complete or partial kernel, edit the *user-facing answer*
down to the bare necessities. Do this last, after the diagnosis, policy, and
actions are coherent.

- Keep only claims needed to understand the diagnosis, make the decision,
  follow the policy, execute or assess the proposed actions, or see a material
  constraint, uncertainty, tradeoff, or consequence.
- Preserve required evidence and proof, including the Existing Capability
  Check and the full numbered action list when applicable. Compress their
  wording; do not silently remove them.
- Delete repeated rationale, background that does not change a decision,
  decorative framing, redundant headings, and sentences that restate a bullet.
- Consolidate points that make the same claim or serve the same purpose. Give
  each remaining point one distinct idea; split a point that contains separate
  ideas, and remove any overlap between points.
- Keep a decision-bearing question only when its answer changes the kernel.
- Recheck the shortened answer: each action must still trace to the diagnosis
  and policy, and the reader must still know what decision or next step is
  required. If shortening hides either, restore the missing fact.
