# Adversarial Review

Use this review while converging on a solution and before finalizing Coherent Actions. Test the strongest decision-relevant challenges to the candidate approaches, then check that actions implement the selected approach. The review is a quality gate, not a separate strategy document.

## Review the Reasoning Chain

Check:

- Does the problem evidence support the Diagnosis?
- Does the Diagnosis support the Guiding Policy, when one is included?
- Does each candidate approach fit the Diagnosis, Guiding Policy, and known constraints?
- Is there a material assumption, counterexample, failure condition, or plausible alternative that would change which approach should be selected?
- After selection, do the proposed actions implement that approach and follow from the reasoning?

Challenge only claims or assumptions that could change the decision. Do not generate objections for their own sake or enumerate every imaginable risk.

## Resolve the Review

- If a challenge breaks the reasoning, revise the Diagnosis, Guiding Policy, candidate approaches, or actions before finalizing the plan.
- If a material uncertainty cannot be resolved from available evidence, identify it as an unknown and ask the user only if their decision is needed.
- If the reasoning holds, retain the plan and state briefly why the strongest challenge does not change it.

## Keep It Consumable

When the review is useful to show, use this compact format:

- **Strongest objection:** What could make the approach wrong?
- **Decision impact:** Would it change the direction or expose a failure condition?
- **Disposition:** Revise, retain, or stop—and why.

Run a brief internal check for straightforward actions. Show a review block when the user requests adversarial review or when a material challenge changes, qualifies, or blocks the recommendation. Do not add a review section when there is no decision-relevant finding to report.
